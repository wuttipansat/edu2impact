# Template สำหรับทีมคอนเทนต์

โฟลเดอร์นี้มีตัวอย่าง record สำหรับคัดลอกไปใส่ในไฟล์ `data/*.json` ไม่ต้องอัปโหลดขึ้นเว็บไซต์ (เว็บไม่ได้อ่านไฟล์ในโฟลเดอร์นี้)

| ไฟล์ | ใช้กับ |
| --- | --- |
| `workshops.template.json` | `data/workshops.json` มี 2 ตัวอย่าง: โพสต์ที่มีวันที่จัด และเวิร์กช็อปที่ดัดแปลงจากงานวิจัย/นวัตกรรม (ไม่มีวันที่ เชื่อมกลับไปที่งานต้นทาง) |

## วิธีใช้

1. เปิด `templates/workshops.template.json` แล้วคัดลอก record ที่ต้องการ (ตั้งแต่ `{` ถึง `}` ของรายการนั้น)
2. วางต่อท้ายใน `data/workshops.json` (คั่นด้วยเครื่องหมาย `,` จาก record ก่อนหน้า)
3. แก้ข้อความทุกช่องให้เป็นข้อมูลจริง และเปลี่ยน `id` ให้ไม่ซ้ำกับ record อื่น
4. รัน validator (ดูหัวข้อด้านล่าง) จนผ่าน แล้วจึงอัปโหลด

## หน้า Workshop แสดงอะไร

หน้า Workshop เป็นลิสต์ **โพสต์เวิร์กช็อป** คือบทความหรือสรุปเวิร์กช็อปที่ EDU2IMPACT เคยจัด ทุก record ใน `data/workshops.json` จะแสดงเป็นโพสต์หนึ่งแถว เรียงตามลำดับในไฟล์ (อยากให้ขึ้นก่อนก็ย้าย record ขึ้นไปไว้ข้างบน) ไม่มีกลุ่ม "กำลังจะมาถึง" หรือ "ที่ผ่านมา" แล้ว

- แต่ละแถวแสดงแค่ไอคอนเอกสารกับชื่อเรื่อง คลิกแล้วไปหน้ารายละเอียด ชื่อเรื่องจึงควรบอกได้ในตัวว่าเป็นเวิร์กช็อปเรื่องอะไร
- เขียนเนื้อหาให้สั้น 2–3 ย่อหน้าก็พอ เน้นว่าผู้เข้าร่วมได้ลงมือทำอะไร ไม่ต้องอ้างอิงงานต้นทางในเนื้อหา เพราะการ์ดของงานที่เชื่อมไว้ (`related`) จะขึ้นท้ายหน้าเอง
- แต่ละโพสต์คือเวิร์กช็อปที่หน่วยงานติดต่อขอให้จัดได้ เช่น ดัดแปลงจากโพสต์นวัตกรรมหรืองานวิจัย (ดู Hemo-Link และหลักสูตรนครนนทบุรีใน `data/workshops.json`) แล้วเชื่อมกลับไปที่โพสต์ต้นทางด้วย `related`
- หน้ารายละเอียดของทุกเวิร์กช็อปมีปุ่ม **ติดต่อทีมงาน** ลิงก์ไปหน้า "ติดต่อเรา" ขึ้นต่อจากเนื้อหาเอง ไม่ต้องใส่ในไฟล์

`date` ต้องมี key นี้เสมอ แต่ใส่ได้ 2 แบบ:
- **วันที่จัดเวิร์กช็อป** รูปแบบ `YYYY-MM-DD` (ปี ค.ศ.) เช่น `"2026-09-12"` จะแสดงเป็นวันที่ภาษาไทยในแถวและหน้ารายละเอียด (ตัวอย่างที่ 1 ใน template)
- **สตริงว่าง** `"date": ""` เมื่อไม่ต้องการแสดงวันที่ (ห้ามลบ key `date` ทิ้ง) หน้ารายละเอียดและการ์ดหน้าแรกจะไม่แสดงวันที่ (ตัวอย่างที่ 2)

## ฟิลด์ของ record

| ฟิลด์ | ต้องมี | รูปแบบ | คำอธิบาย |
| --- | --- | --- | --- |
| `id` | ✓ | อักษรอังกฤษตัวเล็ก ตัวเลข และ `-` เช่น `post-research-to-classroom-workshop` | ใช้ในลิงก์ของหน้า ห้ามซ้ำในไฟล์เดียวกัน และไม่ควรเปลี่ยนหลังเผยแพร่ (ลิงก์เก่าจะเสีย) |
| `title` | ✓ | ข้อความ | ชื่อเรื่อง |
| `category` | ✓ (ยกเว้นเวิร์กช็อป) | ข้อความ | ป้ายหมวดของงานวิจัยและนวัตกรรม **เวิร์กช็อปไม่ใช้หมวด** ให้ลบ key นี้ออก |
| `summary` | ✓ | ข้อความ | สรุป 1 ประโยค แสดงใต้ชื่อเรื่องในหน้ารายละเอียด ในการ์ดของงานที่เชื่อมไว้ และในผลค้นหา (ไม่แสดงในหน้ารายการเวิร์กช็อป) |
| `image` | ✓ | `assets/images/<ชื่อไฟล์>.png/jpg/jpeg/webp` หรือ `""` | ภาพหลัก ไฟล์ต้องมีอยู่จริง ใช้ `assets/images/content-placeholder.png` ระหว่างรอภาพจริงได้ |
| `date` | ✓ | `YYYY-MM-DD` หรือ `""` | วันที่จัดเวิร์กช็อป หรือสตริงว่างถ้าไม่แสดงวันที่ |
| `author` | ✓ | ข้อความ (ว่างได้) | ผู้เขียนหรือวิทยากร |
| `featured` | ✓ | `true` / `false` | ใช้กับหน้างานวิจัยเป็นหลัก สำหรับเวิร์กช็อปใส่ `false` |
| `public` | ✓ | `true` / `false` | `true` แสดงบนเว็บ `false` ซ่อนจากทุกหน้า (หน้ารายการ หน้าแรก ผลค้นหา และการ์ดงานที่เชื่อมไว้) ส่วนหน้ารายละเอียดจะขึ้นว่าไม่พบ ใช้ซ่อนงานที่ยังไม่พร้อมเผยแพร่ได้โดยไม่ต้องลบ record |
| `body` | ✓ | array | เนื้อหา แต่ละรายการคือย่อหน้า 1 ย่อหน้า หรือบล็อกภาพ (ดูด้านล่าง) |
| `audience` | – | array ของข้อความ | แสดงเป็น "เหมาะกับ" และใช้เป็นคำค้น |
| `subjects` | – | array ของข้อความ | แสดงเป็น "ใช้ได้กับกลุ่มสาระ" |
| `features` | – | array ของข้อความ | แสดงเป็น "ความสามารถหลัก" (ใช้กับนวัตกรรม เวิร์กช็อปไม่ต้องใส่) |
| `references` | – | array ของข้อความ | แสดงเป็น "อ้างอิง" |
| `related` | – | array ของ `{ "kind": …, "id": … }` | เชื่อมกับงานวิจัย นวัตกรรม หรือเวิร์กช็อปอื่น (ดูด้านล่าง) |

ฟิลด์ที่มีเครื่องหมาย – ไม่บังคับ ถ้าไม่ใช้ให้ลบทั้งบรรทัดออก (อย่าเหลือ array ว่างที่มีข้อความตัวอย่างค้างไว้)

### ภาพแทรกระหว่างย่อหน้า

ใส่ object แบบนี้ใน `body` ตรงตำแหน่งที่ต้องการให้ภาพขึ้น:

```json
{ "image": "assets/images/<ชื่อไฟล์>.webp", "alt": "บรรยายว่าภาพแสดงอะไร", "caption": "คำบรรยายใต้ภาพ (ไม่บังคับ)" }
```

`image` ต้องเป็นไฟล์ที่มีอยู่จริงใน `assets/images/` และต้องมี `alt` เสมอ (ใช้กับโปรแกรมอ่านหน้าจอ) ส่วน `caption` แสดงใต้ภาพและค้นหาได้

## การเชื่อมโยงด้วย `related`

```json
"related": [
  { "kind": "research", "id": "nonthaburi-learning-city-wellbeing-curriculum" },
  { "kind": "innovations", "id": "hemo-link" }
]
```

- `kind` ต้องเป็นอย่างใดอย่างหนึ่ง: `research` (งานวิจัย ใน `data/research.json`), `innovations` (นวัตกรรม ใน `data/innovations.json`), `workshops` (เวิร์กช็อป ใน `data/workshops.json`)
- `id` ต้องตรงกับ `id` ของ record ที่มีอยู่จริงในไฟล์นั้น (คัดลอกจากไฟล์ หรือดูจากท้ายลิงก์ของหน้า เช่น `research-detail.php?id=nonthaburi-learning-city-wellbeing-curriculum`)
- แต่ละรายการมีได้แค่ `kind` กับ `id` ห้ามลิงก์หาตัวเอง และห้ามลิงก์ซ้ำ

**ใส่ลิงก์ฝั่งเวิร์กช็อปที่เดียวพอ** เว็บจะแสดงให้ทั้งสองฝั่งเอง:
- หน้ารายละเอียดของเวิร์กช็อปมีการ์ดของงานวิจัย/นวัตกรรมที่เชื่อมไว้ อยู่ท้ายหน้า (ไม่มีหัวข้อ)
- หน้ารายละเอียดของงานวิจัย/นวัตกรรมนั้นจะแสดงเวิร์กช็อปที่ลิงก์มาหาโดยอัตโนมัติ ไม่ต้องแก้ `research.json` หรือ `innovations.json`
- ค้นหาชื่อของงานที่เชื่อมไว้ (เช่น "Hemo-link") แล้วจะเจอเวิร์กช็อปนั้นด้วย

ถ้าปลายทางถูกลบหรือ `id` พิมพ์ผิด หน้าเว็บจะข้ามลิงก์นั้นไปเฉย ๆ แต่ validator จะแจ้ง error ให้แก้

## ตรวจก่อนอัปโหลด

รันจากโฟลเดอร์หลักของโปรเจกต์ (ต้องมี Python 3):

```
python3 tools/validate_content.py
```

ถ้าผ่านจะขึ้น `All content files passed validation.` ถ้าไม่ผ่านจะบอกไฟล์ `id` และตำแหน่งที่ผิด เช่น

```
workshops.json: post-research-to-classroom-workshop: related[1] points to innovations/hemo-lnk, which does not exist in innovations.json
```

ข้อผิดพลาดที่พบบ่อย: ลืม `,` ระหว่าง record, ลบ key `date` แทนการใส่ `""`, `id` ซ้ำ, ภาพไม่มีอยู่จริง, บล็อกภาพไม่มี `alt` และ `related` ชี้ไปที่ `id` ที่ไม่มีอยู่

## ตัดคำภาษาไทย (ก่อนอัปโหลดทุกครั้งที่แก้เนื้อหา)

เบราว์เซอร์ตัดบรรทัดภาษาไทยด้วยพจนานุกรมในตัว ซึ่งมักตัดคำทับศัพท์และชื่อเฉพาะกลางคำ เช่น "เวิร์|กช็อป" เว็บจึงใช้ไฟล์ `data/thai-breaks.json` บอกตำแหน่งรอยต่อคำของสรุปและเนื้อหาแต่ละย่อหน้า ไฟล์นี้สร้างอัตโนมัติ ห้ามแก้เอง

ติดตั้งครั้งแรกครั้งเดียว แล้วรันหลังแก้ `research.json` `innovations.json` หรือ `workshops.json`:

```
pip install pythainlp
python3 tools/segment_thai.py
```

แล้วอัปโหลด `data/thai-breaks.json` ไปพร้อมไฟล์ JSON ที่แก้ ถ้าลืมรัน หน้าเว็บยังแสดงผลได้ปกติ แค่ย่อหน้าที่แก้จะกลับไปตัดบรรทัดแบบเดิม และ `validate_content.py` จะเตือนว่ามีกี่ย่อหน้าที่ยังไม่ได้ตัดคำ
